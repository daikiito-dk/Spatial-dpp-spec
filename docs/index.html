spatial-dpp
v0.1.0 draft

Geometry, physics, and EU compliance — in one open, machine-readable format.

spatial-dpp binds a non-destructive 3D/CAD reference, the physical properties a simulator needs, and the regulatory truth of a product (BOM, Digital Product Passport, Cyber Resilience Act) into a single document with a strict validator, CLI, and WASM bindings.

Layer 1

Geometry Reference

URI + SHA-256/512 content hash into glTF / USD / STEP / OBJ / STL. Non-destructive: your CAD stays where it is.

+
Layer 2

Physical Properties

Mass, center of mass, friction, stiffness, and kinematic joints with limits — in units physics engines consume directly.

+
Layer 3

Compliance / DPP

Bill of materials, material composition, recyclability, disassembly steps with hazards, SBOM/HBOM refs, CRA records.

01One document, three truths

// examples/ev_battery_pack.json
{
  "metadata": { "spec_version": "0.1.0", "document_id": "urn:product:ev-battery-pack-2026", "created": "2026-09-01T00:00:00Z" },
  "objects": [
    {
      "id": "ev_pack", "label": "EV Battery Pack",
      "geometry":  { "format": "gltf", "uri": "urn:example:meshes/ev-pack-v3",
                      "hash": { "algorithm": "sha256", "value": "3fa85f64…" } },
      "physical":  { "mass_kg": 12.4, "center_of_mass": [0.5, 0.5, 0.41],
                   "friction": { "static": 0.6 }, "stiffness": { "youngs_modulus_pa": 69000000000.0 } },
      "compliance": {
        "material_composition": [ { "material_id": "li_ion_cells", "fraction": 0.55 } ],
        "recyclability_rate": 0.62,
        "dpp": { "passport_id": "urn:dpp:eu:ev-pack-2026", "sbom_ref": "https://…/sbom.json" },
        "disassembly": { "steps": [ { "order": 3, "action": "deactivate",
                          "target": "cell_array", "hazard": "thermal_runaway" } ] },
        "cra": { "conformance": "conformant", "support_period_until": "2032-09-01T00:00:00Z" }
      }
    }
  ]
}

Units live in field names (mass_kg, lower_deg, youngs_modulus_pa). Center of mass is bounding-box normalized [0,1], so values survive unit and scale changes.

02Strict, deterministic validation

Two layers, one report: structural conformance (V-01) plus a semantic rule for every physical and compliance value. Binary formats (MessagePack, Protobuf) produce identical reports — every structural rule has a semantic twin, so nothing bypasses the rules.

CodeRuleCodeRule
V-02mass is finite and > 0 V-09material fractions sum to 1 ± 0.001
V-05center of mass within [0,1]³ V-12disassembly steps ordered & targets resolve
V-06joint axes are unit vectors; limits ordered V-13content hashes match their algorithm
V-08joint parent/child resolve inside the document V-14timestamps are valid RFC 3339

Plus warnings (W-01 missing hash, W-02 unknown CRA conformance, W-03 no disassembly plan). Full normative table: SPEC.md §6.

04Formats & integrations

TargetHow
Canonical JSON / JSON-LDSorted keys, shortest round-trip decimals; JSON-LD adds @context for linked-data joins.
MessagePack / ProtobufBinary transport; enums as strings for forward compatibility; semantic-identical round-trips proven by tests.
glTF 2.0EXT_spatial_dpp extension: one node = one object; loaders without support keep working.
OpenUSDDeterministic .usda export: physics:mass, PhysicsRevoluteJoint, sdpp:* compliance dictionaries.
DeCAD / OD-BOMdisassembly.plan_ref links to full disassembly constraint graphs of the sister project.

05Why it matters

Physical AI & simulators

Read one file and get collision-relevant physics: mass, center of mass, friction, stiffness, and joint limits — no conversion glue code.

Disaster response & recycling robotics

Machine-readable take-apart steps with per-step hazards (thermal_runaway, asbestos, electrical…) so a robot can plan safe deconstruction of, e.g., damaged EV batteries.

EU compliance built in

Digital Product Passport identifiers, SBOM/HBOM references, and CRA conformance records travel with the asset — auditable at the same path as the geometry.

// examples/ev_battery_pack.json
{
  "metadata": { "spec_version": "0.1.0", "document_id": "urn:product:ev-battery-pack-2026" },
  "objects": [
    {
      "id": "ev_pack", "label": "EV Battery Pack",
      "geometry":  { "format": "gltf", "uri": "urn:example:meshes/ev-pack-v3",
                      "hash": { "algorithm": "sha256", "value": "3fa85f64…" } },
      "physical":  { "mass_kg": 12.4, "center_of_mass": [0.5, 0.5, 0.41], "friction": { "static": 0.6 } },
      "compliance": {
        "material_composition": [ { "material_id": "li_ion_cells", "fraction": 0.55 } ],
        "recyclability_rate": 0.62,
        "dpp": { "passport_id": "urn:dpp:eu:ev-pack-2026" },
        "disassembly": { "steps": [ { "order": 3, "action": "deactivate",
                          "target": "cell_array", "hazard": "thermal_runaway" } ] },
        "cra": { "conformance": "conformant" }
      }
    }
  ]
}

単位はフィールド名に埋め込み（mass_kg、lower_deg、youngs_modulus_pa）。重心はバウンディングボックス正規化 [0,1] で、単位・スケール変更に強い設計です。

02厳密で決定論的なバリデーション

2層構造で1つのレポート: 構造検証（V-01）+ 物理・コンプライアンス全ルールのセマンティック検証。 MessagePack / Protobuf でもJSONと同一のレポートになります（構造ルールには全て双子が存在するため、バイナリ経由で迂回できません）。

コードルールコードルール
V-02質量は有限かつ > 0 V-09素材比率の合計は 1 ± 0.001
V-05重心は [0,1]³ の範囲内 V-12分解ステップの順序・参照先が解決可能
V-06関節軸は単位ベクトル・可動域は順序どおり V-13コンテンツハッシュがアルゴリズムと整合
V-08関節の親子参照がドキュメント内で解決 V-14タイムスタンプは有効な RFC 3339

警告もあり（W-01 ハッシュ未指定、W-02 CRA適合不明、W-03 分解手順なし）。規範テーブル全文: SPEC.md §6。

05なぜ重要か

フィジカルAI・シミュレータ

1ファイルから質量・重心・摩擦・剛性・関節可動域を直接読める。変換用のグルーコードが不要。

災害対応・リサイクルロボティクス

ステップ単位の危険フラグ（thermal_runaway、asbestos、electrical など）付きの機械可読な分解手順で、破損EVバッテリーなどの安全な解体計画が可能。

EUコンプライアンス内蔵

DPP識別子・SBOM/HBOM参照・CRA適合記録がジオメトリと同一のパスで監査可能。
